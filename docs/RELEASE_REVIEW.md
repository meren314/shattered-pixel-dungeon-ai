# 发布前代码审查与验证

日期：2026-10-21。范围为本发布目录中的桌面 AI 接口、正式 Python 客户端、构建入口、文档和待提交文件；不是对原游戏全部玩法代码的独立安全审计。

## 1. 已处理的问题

1. 原开发目录混有个人存档、备份、对话、地图缓存、游玩记录和机器绝对路径。使用源码目录与正式客户端的明确白名单导出，未复制这些运行数据。Git 忽略规则阻止以后常见运行状态进入提交。
2. 原目录依赖 Android 根构建配置，首次桌面使用可能要求额外 SDK。发布目录的根构建改为桌面专用模块，Gradle Wrapper 从源码重新构建成功，无需 Android SDK。
3. 原接口仅部分路由校验 Origin，缺少 Host 校验。现在所有路由在分发前统一检查 Host 和 Origin，阻止非预期域名及跨域浏览器访问。绑定仍为 127.0.0.1；不将本地服务宣称为有身份认证的远程服务。
4. 旧文档包含历史协议、过时 goto 限制及未随包发布的 reliable_player.py 入口。本包只提供当前规则、能力报告和协议说明，示例指向实际的 player.py，区分原子 HTTP 与 Python 组合操作。
5. 保留 GPLv3 原文、原作者版权及上游说明；新增 NOTICE、使用说明、安全边界和贡献说明。未将派生游戏整体改为 MIT 等不相符许可。
6. 启动脚本保留游戏正常窗口，隐藏后台进程控制台。未改变原用户游戏和存档，也没有自动合并其他安装版存档。

## 2. 已核查的接口逻辑

1. AiProbe 的普通地形与实体观测通过 heroFOV 过滤，秘密地形使用玩家显示名称。怪物输出近似血条，未开放精确隐藏 HP；已见堆使用 heap.seen，未开放未开启容器内容。该检查针对当前输出实现，不声称自动证明所有未来扩展均符合边界。
2. 正式 ReliableClient 提交前持久化请求编号和请求体；未知结果阻止新动作，resume 查询回执而非重发。ACK 后才推进地图和事件基线；单消费者锁阻止客户端并发修改同一日志。
3. 导航只使用公开地图记忆，执行中复核视野和危险；复合交互到达后再检查目标。到达、接受、完成和等待选择具有不同语义。

## 3. 本次验证结果

1. 30 项协议/导航测试、9 项兼容辅助函数测试、6 项上下文工具测试，共 45 项通过。使用临时目录和模拟接口，没有启动游戏或操作存档。
2. 从本发布目录构建 `:desktop:installDist` 成功；首次 15 个任务执行，随后重复检查均为 UP-TO-DATE。环境为 Windows、JDK 26.0.1、Python 3.14.5、Gradle Wrapper 9.5.0。
3. HTTP 策略测试 8 个案例通过；通过真实 HttpServer 与 AiProbe 分发器验证 9 个案例通过，覆盖面板、capabilities、action、chat 的外域拦截及正常 capabilities 响应。这些测试不启动图形游戏。
4. GitHub Actions 配置已加入，但尚未推送到 GitHub，因此未声称云端 CI 已通过。JDK 21/Python 3.12 的组合由 CI 配置指定，本机未单独验证该组合。

## 4. 尚存边界

1. Java 接口仍集中在较大的 AiProbe 类中，维护成本较高；本次未为发布而重构玩法逻辑。原生兼容 HTTP 调用仍可能绕过 Python 客户端的部分可靠性保护。
2. 本地日志与请求回执会持续增长，未实现自动清理。未知动作恢复依赖这些记录，清理需要明确的保留与归档策略。
3. 未重新执行历史全套图形游戏集成测试，未进行新模型通关测试，也未验证 Linux/macOS 启动器。不得将历史验收结果包装为本发布包的当前全量实测。
4. 本包保留上游新闻和更新服务源码；它们可能访问原作者站点。二进制正式发行前还应审查更新链接和随包第三方依赖许可证。本次交付为源码发布包。
5. 本机源码没有原 Git 历史，版本名称可核实为 4.0.2，但无法通过现存记录确定全部文件对应的唯一上游提交。NOTICE 明确保留这一来源限制。
6. 原游戏文件包含大量既有行尾空白，首次导入时全仓库 diff --check 会报告这些历史格式问题。本次未批量重排上游文件；新增文档、客户端、测试及新安全策略文件的定向空白检查通过。
